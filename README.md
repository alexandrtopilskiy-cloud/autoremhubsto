# AutoRemHub

Облачная платформа для автосервисов. Каждая СТО регистрируется сама и работает в своём отдельном кабинете: данные разных СТО изолированы друг от друга.

## Что уже есть

### Этап 1

- Регистрация СТО и владельца, вход по email и паролю, выход.
- Клиенты: физлица, ИП и юрлица, поиск по имени, телефону, госномеру и VIN, скидка клиента, архив.
- Автомобили клиента: марка, модель, год, госномер, VIN, цвет.
- Заказ-наряды: сквозная нумерация внутри СТО, стадии (новый, согласование, в работе, готов), работы по нормочасам, запчасти и материалы, скидки по строкам, оплаты и возвраты (наличные, карта, безнал, СБП), остаток к оплате, проведение с закрытием и его отмена, печатная форма.
- История заказ-нарядов в карточке клиента.

### Этап 2

- Настройки СТО: название, город, цена нормочаса, организации (юрлица и ИП) с реквизитами для печатной формы.
- Сотрудники-исполнители с процентом от работ, назначение исполнителя на работу в заказ-наряде.
- Пользователи и роли: владелец, администратор, менеджер, механик. Владелец и администратор дают и закрывают доступ, при закрытии сессии пользователя завершаются. Один человек может работать в нескольких СТО под одним логином.
- Справочник работ (по нормочасам или с фиксированной ценой) и номенклатура товаров, подбор из них в заказ-наряд.

### Этап 3

- Склад: поставщики, приходные накладные с проведением, остатки по товарам со средней закупочной ценой и суммой. Товары заказ-наряда списываются со склада при проведении и возвращаются при отмене проведения.
- Касса: при регистрации СТО создаются касса и расчётный счёт, можно добавить свои. Оплаты заказ-нарядов попадают в кассу (наличные) или на счёт (остальное), можно выбрать вручную. Приход и расход по статьям, оплата поставщику, перемещение между кассами, журнал за период с итогами.

Полный перечень функций и решения по ним: [документ с анализом AutoDealer](https://claude.ai/code/artifact/6d679436-d45f-4e3e-8080-887a364b4903).

### Этап 4

- Запись на сервис: посты (рабочие места) в настройках, календарь «день» по постам с записью кликом по свободному времени, вид «неделя», загрузка каждого поста в процентах от рабочего дня.
- Карточка записи: время, пост, клиент из базы или новый (имя и телефон), автомобиль, причина, ориентировочная сумма, мастер. Этапы: новая, подтверждена, в работе, выполнена, отказ. Пересечения на одном посту запрещены.
- Список записей с фильтрами по периоду, этапу и посту.
- Заказ-наряд из записи в один клик: новый клиент заводится в базу, запись связывается с заказ-нарядом.
- Часовой пояс и рабочие часы СТО в настройках.

### Этап 5

- Раздел «Отчёты» (владелец, администратор, менеджер). Монитор: остатки денег по кассам и счетам, деньги, выручка, себестоимость и маржа за сегодня и вчера, заказ-наряды в работе по стадиям, приём за неделю по дням, новые и вернувшиеся клиенты, топ-10 марок.
- Отчёты за период: реестр заказ-нарядов, выполненные работы, исполнители (выработка и вознаграждение по % от работ), менеджеры (продажи и вознаграждение по % от продаж), ДДС по статьям и кассам, рекламные источники. На текущий момент: долги клиентов и долги перед поставщиками. Остатки склада на конец выбранного дня.
- Любой отчёт выгружается для Excel (CSV с разделителем «;», открывается двойным щелчком).
- У клиента появилось поле «Откуда узнал», у сотрудника — процент от продаж.
- Выручка считается по проведённым заказ-нарядам на дату проведения, реестр — по дате приёма.

### Этап 6

- Файлы и фото к заказ-наряду, калькуляции и приходной накладной (до 10 МБ на файл, хранятся в базе). Картинки и PDF открываются в браузере, остальное скачивается.
- Калькуляции: предварительный расчёт для клиента со строками из справочников или вручную, статусы, печать. Одной кнопкой калькуляция превращается в заказ-наряд.
- Рекомендации клиенту: добавляются в заказ-наряде, строка, от которой клиент отказался, переносится в рекомендации одним нажатием. Открытые рекомендации видны в карточке клиента и в новых нарядах, переносятся в наряд, печатаются в заказ-наряде и списком для обзвона.
- Требования на запчасти: мастер запрашивает товар со склада из заказ-наряда, кладовщик выдаёт или отклоняет на вкладке «Склад → Требования». Выданное попадает в наряд, списание — при проведении.
- Сводка заказ-наряда: себестоимость товаров, вознаграждения исполнителей и менеджера, прибыль, отношение запчастей к работам.
- Журнал всех документов: заказ-наряды, калькуляции, приходные накладные, требования за период.

### Этап 7

- Акт осмотра в заказ-наряде: повреждения на схеме кузова (место, вид, уточнение), уровень топлива, комплектность, отметки «грязный автомобиль» и «принят в тёмное время», примечания. Печатная форма акта со схемой, фото из вложений и подписями.
- У телефона клиента в заказ-наряде и записи — «Позвонить», SMS, WhatsApp и Telegram с готовым текстом: «автомобиль готов, к оплате …» для готового наряда и напоминание о визите для записи.

### Этап 8

- Продажи без ремонта (реализации): покупатель из клиентов или розничный, цена из справочника и скидка клиента, проведение списывает товар по средней закупочной цене. Оплата и возврат идут в выбранную кассу, долг попадает в отчёт «Долги», выручка и себестоимость — в монитор. Печать товарного чека.
- Заказы поставщикам: цена подставляется из последнего прихода, бланк для отправки, статусы «черновик → отправлен → получен». «Товар пришёл» создаёт черновик приходной накладной с теми же строками.
- Списания с причиной: списать больше остатка нельзя.
- Инвентаризация: документ заполняется всеми товарами с остатком, вписывается фактическое количество, видна разница в штуках и рублях. При проведении учётный остаток пересчитывается на момент проведения, разница становится движением склада.
- Все четыре вида документов есть в общем журнале «Документы».

### Этап 9

- Схема зарплаты в карточке сотрудника: процент исполнителя от работ (от стоимости без скидки или от конечной), процент менеджера от работ и отдельно от товаров (от стоимости, конечной стоимости или прибыли), начисление только по полностью оплаченным заказ-нарядам. В справочнике работ можно задать свой процент исполнителю за конкретную работу. Отчёты «Исполнители», «Менеджеры» и сводка заказ-наряда считают по той же схеме.
- Расчёт зарплаты за месяц (Сотрудники → Зарплата): за работы, как менеджер, премии, удержания, начислено, выплачено и остаток к выплате на конец месяца, с фильтром по предприятию.
- Премии и удержания с основанием, выдача зарплаты расходом из кассы по статье «Зарплата». Расчётный листок сотрудника с разбивкой по заказ-нарядам, для печати.

### Этап 10

- Права доступа по разделам (запись, заказ-наряды, клиенты, склад, касса, отчёты, документы, справочники, сотрудники, настройки) с уровнями «нет доступа → просмотр → правка → создание → полный» и отдельными правами давать скидки, менять цены в документах и видеть закупочные цены. Права проверяются в каждом действии на сервере, недоступные разделы пропадают из меню.
- Свои роли СТО (Настройки → Роли и права): название и матрица прав, назначаются пользователю вместо встроенной. Встроенные роли «Администратор», «Менеджер», «Механик» работают как раньше, их права показаны для справки.
- Без права на закупочные цены скрыты закупка и сумма по закупке на складе, себестоимость и маржа в мониторе, отчёт «Склад на дату», приходы и заказы поставщикам, прибыль в сводке заказ-наряда.

### Этап 11

- Группы товаров в справочнике: фильтр по группе в справочнике и на складе, в выборе товара для документов товары сгруппированы. При удалении группы товары остаются без группы.
- Штрихкод товара (уникален в пределах СТО): поиск по нему в справочнике и на складе, а в строках прихода, продажи, заказа поставщику, списания, инвентаризации и заказ-наряда товар можно добавить сканером — код и Enter.
- Минимальный остаток: на складе видны минимум и сколько докупить, фильтр «только ниже минимума». В заказе поставщику кнопка «Добавить дефицит» добавляет недостающее количество по всем товарам или по группе с ценой последнего прихода.

### Этап 12

- Категории цен (Справочники → Категории цен): наценка или скидка к базовой цене товара в процентах и своя цена нормочаса. Для каждой категории есть прайс со своими ценами товаров, пустая цена считается по проценту с округлением до рубля.
- Категория назначается клиенту в карточке. При добавлении товара или работы из справочника в заказ-наряд, калькуляцию или продажу цена берётся по категории клиента, скидка клиента применяется поверх. Менять категории, прайсы и категорию клиента может только пользователь с правом менять цены.

### Этап 13

- Общие справочники (Справочники → Общие справочники): единицы измерения, производители, цвета автомобилей, виды ремонта, типы повреждений, комплектность, рекламные источники, причины списания. Пока список не меняли, действует стандартный; значения можно добавлять, переименовывать, удалять, менять порядок и вернуть стандартный список.
- Справочники подсказывают при вводе единицы и бренда товара, цвета автомобиля, причины обращения в записи и заказ-наряде, источника клиента и причины списания. В акте осмотра типы повреждений и комплектность выбираются из справочников СТО.

### Этап 14

- Корзина (Документы → Корзина): черновики заказ-нарядов, калькуляции, приходы, продажи, списания, инвентаризации, заказы поставщикам и кассовые операции удаляются в корзину. Документ из корзины восстанавливается с прежним номером, строками, актом осмотра и связями с рекомендациями и записями или удаляется навсегда вместе с файлами.
- Проведённые документы, заказ-наряды и продажи с оплатами, калькуляции, по которым создан заказ-наряд, удалить нельзя, пока не отменить проведение и оплаты. Удаляет и восстанавливает пользователь с полным доступом к разделу документа; в корзине видно, кто и когда удалил.

## Стек

TypeScript, Next.js 15 (App Router, server actions), React 19, PostgreSQL 16, Prisma 6, Tailwind CSS 4, Vitest.

## Запуск

```bash
cp .env.example .env          # поправьте DATABASE_URL и TEST_DATABASE_URL под свой Postgres
npm install
npm run db:migrate            # создаёт таблицы
npm run db:seed               # демо-СТО: demo@autoremhub.local / demo12345
npm run dev                   # http://localhost:3000
```

Проверки: `npm run typecheck`, `npm run lint`, `npm test` (нужна отдельная тестовая база, она очищается перед каждым тестом), `npm run build`.

## Устройство

- `prisma/schema.prisma` — модель данных. Все рабочие таблицы несут `companyId`.
- `src/lib/services/*` — бизнес-логика. Каждая функция принимает `companyId` из сессии и проверяет, что связанные записи принадлежат этой же СТО (`src/lib/tenant.ts`).
- `src/lib/auth-core.ts` — пароли (bcrypt) и сессии: в cookie лежит случайный токен, в базе только его sha256.
- `src/lib/money.ts` — деньги хранятся в копейках, количество и нормочасы дробные.
- `src/app` — страницы и server actions.
