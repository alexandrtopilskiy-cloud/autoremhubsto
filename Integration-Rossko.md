# План интеграции с Rossko

## 1. Цель и границы интеграции

Цель: Автоматизировать перенос заказов, оформленных на сайте Rossko, в систему `AutoRemHubSto` в виде приходных накладных с последующим списанием запчастей в заказ-наряды.

Что входит в интеграцию:

- Настройка: Ввод и безопасное хранение ключей `API` (KEY1, KEY2) в разделе «`Управление → Интеграции`».
- Получение заказов: Запрос списка заказов из Rossko по `API` за выбранный период (или по статусу).
- Формирование прихода: Создание черновика приходной накладной (`Receipt`) на основе выбранного заказа Rossko.
- Связывание: Связывание строк прихода с номенклатурой `AutoRemHubSto` (по артикулу и бренду).
- Использование в ЗН: Выбор товаров из проведенной приходной накладной в заказ-наряд.

## 2. Этап 1: База данных и Безопасность (Фундамент)

Для работы в SaaS-режиме ключи доступа должны храниться в зашифрованном виде и быть изолированы по компаниям (`companyId`).

## 2.1. Схема БД (`prisma/schema.prisma`)

_Enum_ `IntegrationProvider`: `ROSSKO`, `EUROAVTO`, `AUTOEVRO`, `TECHNOVECTOR`.

Модель `Integration`:

- `id` (String, PK)
- `companyId` (String, FK)
- `provider` (IntegrationProvider)
- `encryptedCredentials` (String) — JSON с ключами, зашифрованный AES-256-GCM.
- `isActive` (`Boolean, default true`)
- `createdAt`, updatedAt
- `@@unique([companyId, provider])`

Связь в `Company`: `integrations Integration[]`

## 2.2. Утилита шифрования (`src/lib/crypto.ts`)

- Функции `encrypt(text)` и `decrypt(ciphertext)` с использованием `crypto` (AES-256-GCM).
- Ключ берется из переменной окружения `ENCRYPTION_SECRET` (добавить в `.env`).

## 2.3. Сервисный слой (`src/lib/services/integrations.ts`)

- `saveIntegration(provider, credentials)`: Шифрует и сохраняет ключи. Проверяет права (`OWNER` или `ADMIN`).
- `getIntegration(provider)`: Расшифровывает и возвращает ключи для текущей компании.
- `deleteIntegration(provider)`: Удаляет интеграцию.

## 4. Этап 3: Клиент API Rossko (Бэкенд)

Создание обертки для работы с SOAP API Rossko.

## 4.1. Клиент (src/lib/services/rossko.ts)

- Использовать библиотеку `soap` или `fetch` с формированием XML.
- Метод `checkConnection(credentials)`: Вызов `GetOrders` с лимитом 1. Возвращает `true`, если ответ `200` и нет ошибки авторизации.
- Метод `fetchOrders(credentials, dateFrom, dateTo)`: Вызов `GetOrders`. Возвращает массив заказов с их статусами и списком товаров.

## 4.2. Server Actions (`src/app/(dashboard)/settings/integrations/actions.ts`)

- `saveRosskoAction(formData)`: Обработка формы сохранения ключей.
- `checkRosskoAction()`: Проверка соединения и возврат статуса в UI.

## 5. Этап 4: Синхронизация заказов и Приход товара

Интеграция в раздел «Склад → Приход товара».

## 5.1. UI в «Приход товара»

- На странице списка приходных накладных добавить кнопку «Получить из Rossko».
- При нажатии открывается модальное окно с загрузкой (спиннер).

Система запрашивает заказы из Rossko. Отображается таблица:

- Номер заказа Rossko.
- Дата.
- Статус.
- Сумма.
- Кнопка «Создать приход».

## 5.2. Логика создания прихода (`src/lib/services/stock.ts` или новый `rossko-receipt.ts`)

При нажатии «Создать приход»:

- Создается черновик `Receipt` в БД (status: `DRAFT`).
- Строки (`ReceiptLine`) заполняются из данных Rossko.
- Сопоставление товаров: Для каждой строки ищется `Product` в AutoRemHub по `article` и `brand`. Если товар не найден — предлагается создать его (или он создается автоматически как «Без названия» с артикулом Rossko).
- Пользователь перенаправляется на страницу созданного черновика прихода для проверки цен и количеств.

## 5.3. Связь с `SupplierOrder`

- Если заказ в AutoRemHub был создан вручную (в разделе «Заказы поставщикам»), при получении прихода из Rossko можно связать его с существующим заказом (по номеру или артикулам), чтобы обновить статус на «Получен».

## 6. Этап 5: Использование в Заказ-наряде

Обновление карточки заказ-наряда (ЗН).

## 6.1. Кнопка «Добавить из приходной накладной»

- В блоке «Запчасти и материалы» (вкладка «Работы и запчасти») добавить кнопку рядом с «Из номенклатуры».
- При нажатии открывается модальное окно со списком проведенных приходных накладных (или свободных остатков по ним).

## 6.2. Логика добавления

- Пользователь выбирает приходную накладную и конкретные позиции.
- Система добавляет `WorkOrderItem` в ЗН.
- Себестоимость: Цена закупки берется из `StockMove` (средняя себестоимость), чтобы правильно считать маржу.
- Цена продажи: Берется из справочника `Product` (с учетом категории цен клиента).
